# 衣栈 · 服装店多店后台管理系统

面向**多门店服装零售**的后台管理系统：库存出入库、销售记账、退货处理、经营/个人双看板、账号权限体系。

前端 **Vue3 + Pinia + Vite + ElementPlus + Axios + ECharts**（纯 JavaScript，无 TypeScript）
后端 **NestJS + Prisma + SQLite**（可一键切换 MySQL）

仓库地址：<https://github.com/mateboys/erp-store-admin>

> **仓库内已附带可运行的演示数据库** `server/prisma/dev.db`（约 200KB，含 3 家门店、10 个商品、470 张演示销售单及近 60 天趋势数据）。克隆后按下面「快速启动」三步即可看到完整界面，无需自己造数据。
> 数据库内全部为**种子脚本生成的演示数据**，不含任何真实经营数据或个人信息。

## 一、快速启动

**环境要求**：Node.js ≥ 18（推荐 20/22）、npm ≥ 9。

### 1. 拉代码

```bash
git clone https://github.com/mateboys/erp-store-admin.git
cd erp-store-admin
```

### 2. 启动后端（端口 3000）

```bash
cd server
npm install

# 复制环境变量模板（仅首次）
cp .env.example .env

# 生成 Prisma Client
npx prisma generate

# 启动（开发模式，热重载）
npm run start:dev
```

> 上面四步也可以用一条命令搞定（自动检查 Node 版本、复制 .env、装依赖、生成 Prisma）：
> ```bash
> cd server && npm run init
> ```
>
> 仓库已自带 `server/prisma/dev.db`，**不需要**执行 `npx prisma db push`。
> 后端启动时会自动做三件事（都是幂等的，已有数据就跳过）：
> ① 建商品类别（尼斯分类）② 建演示门店与账号 ③ 首次启动才写入演示销售单。

### 3. 启动前端（端口 5173）

```bash
cd web
npm install
npm run dev
```

### 4. 打开

浏览器访问 **http://localhost:5173** ，用下面的演示账号登录即可。

> 前端已配置 `/api` 与 `/uploads` 代理到 `http://localhost:3000`，无需额外设置跨域。
> 若 3000 / 5173 被占用，改端口：后端改 `server/.env` 的 `PORT`（同时改 `web/vite.config.js` 的 `proxy.target`），前端改 `web/vite.config.js` 的 `server.port`。

### 生产构建

```bash
cd server && npm run build && npm start        # 后端产物在 server/dist，监听 3000
cd web    && npm run build                     # 前端产物在 web/dist，交给 nginx 等静态服务器
```

## 三、功能清单

### 1. 多店与登录
- 管理员登录后顶部可切换 **「公司总览（全部店）」** 或 **任意分店**，全站数据随切换实时刷新。
- 店长 / 营业员登录后**锁定**在管理员配置的门店，无切换入口；后端也会强制按所属门店过滤数据，绕不过去。
- 顶部还有「修改密码」。

### 2. 权限体系（角色默认权限 + 账号追加授权）

| 权限点 | 管理员 | 店长 | 营业员 |
| --- | :---: | :---: | :---: |
| 查看经营总览 / 个人总览 | ✅ | ✅ | ✅ |
| **查看成本 / 毛利 / 毛利趋势** | ✅ | ❌（可单独授权） | ❌（可单独授权） |
| 查看商品 | ✅ | ✅ | ✅ |
| 新增 / 编辑商品 | ✅ | ✅ | ✅ |
| 查看库存 | ✅ | ✅ | ✅ |
| **货品出入库（入库 / 丢失破损 / 退供应商 / 调拔）** | ✅ | ❌（可单独授权） | ❌（可单独授权） |
| 销售记账 | ✅ | ✅ | ✅ |
| 查看销售记录 | ✅ | ✅ | ✅ |
| 修改他人销售单 | ✅ | ❌（可单独授权） | ❌（可单独授权） |
| 门店管理 | ✅ | ❌ | ❌ |
| 账号与权限管理 | ✅ | ❌ | ❌ |

设计要点：
- 入库与出库**共用同一个权限点** `inventory:in`（界面显示为「货品出入库」），不再单列出库权限。
- **勾选「货品出入库」前必须先勾「查看成本与毛利」** —— 因为出入库要填进货价，没有成本权限就拿不到成本价。界面上自动联动：勾上成本权才出现出入库选项，取消成本权会连带取消出入库权。
- 菜单、按钮与后端 `PermissionsGuard` **三重联动**，前端藏按钮不代表安全。

### 3. 库存管理（三个 tab）

页面顶部是一个「门店」选择器（切店后库存列表、出入库记录同步跟着变），下面三个 tab：

#### 3.1 库存列表
- 列表字段：图片 / 货号 / 品名 / 门店（公司总览视角）/ 剩余库存 / 销售价 / **标准成本价** / **进价** / **均价成本** / 库存成本。
- **剩余库存 ≤ 0 显示红色「缺货」**，1–5 件显示橙色告警，>5 绿色。
- 三个成本列的差别：
  | 列 | 数据来源 | 含义 |
  | --- | --- | --- |
  | **标准成本价** | `Product.costPrice` | 该货号的常规进货水平（档案预设），入库时预填进货价 |
  | **进价** | 最近一次入库流水的进货价 | 上一笔实际进货花了多少 |
  | **均价成本** | `Stock.avgCost` | **移动加权平均**，销售结转成本就用这个 |
- 顶部汇总：SKU 数、总件数、库存成本合计。

#### 3.2 商品入库
三种录入方式合并在一个 tab 内，进入后用顶部的**方式卡片**切换：

| 方式 | 说明 |
| --- | --- |
| **扫码枪入库** | 扫码枪当作键盘输入，枪响即入，可连续扫 |
| **拍照扫码入库** | 调用摄像头扫条码（`@zxing/browser`，支持 EAN/UPC/Code128 与 QR），进入该方式自动开摄像头、切走自动关闭释放 |
| **手动入库** | 按货号 / 品名模糊搜索选商品 |

- 成本采用**移动加权平均**计价：`新均价 =（原均价 × 原库存 + 本次进货价 × 本次件数）÷ 新总件数`。
- 入库后即时更新门店库存与销售价；右上角「入库门店」必须选具体门店（公司总览下不提供该选项）。
- **货号不能是 13 位纯数字**（与 EAN-13 条码格式冲突会导致扫错货），前端失焦即提示、后端双重拦截。

#### 3.3 商品出库
录入方式与入库完全一致（扫码枪 / 拍照扫码 / 手动选择），右上角标题为「**出库门店**」，另外多一个**出库方式**：

| 出库方式 | 成本处理 | 库存 | 额外信息 |
| --- | --- | --- | --- |
| **丢失 / 破损** | **不结转成本**（记 0） | 正常减少 | 必填**责任人**；**按售价计赔**（售价 × 件数 = 应赔金额） |
| **退供应商** | **成本清零** | 正常减少 | 无经济损失，不记这笔入库成本 |
| **调拔门店** | 成本随货走 | 源店减、目标店加 | 选调入门店；**目标店生成一条「调拔」入库记录**（来源显示「XX店调入」） |

> **为什么丢失按售价而不是成本**：员工照价赔偿 = 按销售价赔，赔完商品从库存消失、该商品账面价值归零。成本价属于敏感信息，写进员工能看的记录等于直接暴露进货价。调拔是公司内部流转，成本不出体系，所以成本随货转移。

#### 3.4 出入库记录
- 原「入库记录」改名，入库与出库流水**同表**展示：方向列（入库绿 / 出库红）、方式列（扫码·手动·调拔·丢失/破损·退供应商）、件数带正负号、进货价、成本合计、赔偿金额、来源/责任人。
- 顶部三态过滤：**出入库全部（默认）/ 只看入库 / 只看出库**，随时切回。
- 可按门店、货号/品名、日期区间查询。

### 4. 商品管理
- **货号全局唯一**，输入即查重，重复时提示已存在的商品名。
- **货号禁止 13 位纯数字**（防扫错货），前端表单校验 + 后端双重拦截。
- 图片上传（可不传，默认占位图）；支持打印商品标签（含条码/二维码）。
- 商品类型：按《类似商品和服务区分表》尼斯分类内置 **第25类 服装鞋帽**（12 个类似群 / 100+ 小类）及第18/24/26/23 类相关小类，支持**模糊搜索**（输入「裤子」「T恤」「鞋」都能搜到）。
- **有库存的商品不能删除**：按钮置灰并提示「该商品还有 N 件库存，请先清空库存再删除」。判断依据是**跨门店总库存**（不受顶部门店筛选影响），避免在 A 店看到 0 就把 B 店有货的商品删掉；后端删除接口也有同样校验。

### 5. 销售记账
- 搜索货号或品名 → 加入购物车（类似电商购物车），支持多商品、逐行改件数、临时改单价、删除行。
- 汇总总件数 / 应收金额（管理员额外显示成本与毛利）→ 一键统一入账，自动生成订单号并扣减库存。
- 销售记录支持按日期、订单号查询，可查看订单明细（含档案价对比与优惠标记）。
- 开单在事务内做了**库存二次校验**，避免并发同时卖最后一件导致超卖。

### 6. 退货处理
- **关联订单退货**：回算到原单当天（订单的营业额/成本/毛利按有效件数重算，退货金额单独统计）。
- **未关联订单退货**：生成一张金额为负的冲减单，挂在退货当天。
- 支持撤销退货（把货退回库存、冲减单一并删除）。
- 责任人、赔偿金额按上述口径记录。

### 7. 经营总览（ECharts）
- **六张卡片**：今日营业额 / 今日毛利 / 今日订单 / 本月营业额 / 本月毛利 / 本月售出，含**日环比**（对比昨日）与**月环比**（对比上月同期）。
- **趋势图**：时间维度支持 **近 14 天 / 当前月 / 选择某个月 / 近 12 个月 / 自定义起止日期**；指标切换 **营业额趋势 / 毛利趋势 / 双轴对比**。
- **退货趋势图**：退货额（柱）与退货件数（折线）双轴。
- **门店业绩对比**柱状图（单店视角时标题自动变为「门店业绩」）、**库存告警**表（剩余 ≤ 5 件）、**本月热销 TOP 8**。
- 店长 / 营业员看到的总览**不含任何成本、毛利、毛利趋势**，对应卡片与按钮自动隐藏。

### 8. 个人总览
同一套看板结构，但**口径只看本人经手的单据**（`operatorId = 当前登录用户`）：
- 六张卡改成「我今日营业额」「我本月毛利」等个人口径；
- 「我的出入库作业」：本月我入库/出库几笔几件，出库再细分丢失破损 / 退供应商 / 调拔；
- 「我本月热销商品 TOP」、「我的退货处理」。

### 9. 其它
- 门店管理：新增 / 编辑 / 停用 / 删除，查看各店人员数、库存件数、累计营业额。
- 账号权限：新增账号、改角色、改所属门店、追加授权、停用、重置密码、删除。

## 四、数据模型与口径

```
Store ──┬── Stock ──── StockBatch（出入库流水）
        │      └───── Product（商品档案：标准成本价 / 销售价 / 条码）
        ├── User（operatorId：谁经手的）
        └── Order ──── OrderItem（销售明细，带货号/品名/价格快照）
                    └── SalesReturn（退货单，带货号/品名/价格快照）
```

**快照 vs 实时关联**（改商品档案时的影响面）：

| 表 | 货号 / 品名 | 价格 | 改档案后 |
| --- | --- | --- | --- |
| `OrderItem` / `SalesReturn` | ✅ 快照 | ✅ 快照 | **完全不变**，历史可追溯 |
| `StockBatch` / `Stock` | ❌ 实时关联 | ✅ 快照 | 货号品名跟着变，金额不变 |

所以：**改售价 / 标准成本价完全不影响任何历史金额与毛利**，可以放心改。

**三个成本口径**：

| 概念 | 存放位置 | 决定方 | 用途 |
| --- | --- | --- | --- |
| 标准成本价 | `Product.costPrice` | 手工填 | 入库时预填进货价 |
| **均价成本** | `Stock.avgCost` | **系统移动加权算出** | 算毛利、算库存价值（**每个门店都不一样**） |
| 进货价 | `StockBatch.costPrice` | 每笔实际填 | 记账、看历史花了多少钱 |

## 六、技术要点

- **权限三层校验**：前端路由 `meta.perm` → 菜单/按钮 `v-if` → 后端 `PermissionsGuard`，缺一不可。
- **数据范围隔离**：后端所有查询统一走 `storeWhere()`，非管理员强制 `storeId = 用户所属门店`，避免越权查看他店数据。
- **金额精度**：所有钱的计算统一走 `server/src/common/money.ts`（`round2 / lineAmount / lineProfit / sumAmount / subAmount`），**明细逐行先取整到「分」再汇总** → 单据总额 = Σ 已取整的明细，接口里不再出现 `161.09999999999999` 这种浮点尾巴；业务代码禁止再写裸 `toFixed(2)`。
- **环比口径**：本月 vs 上月同期（上月 1 号至上月同一天），今日 vs 昨日。
- **图表自适应**：`EChart.vue` 用 `ResizeObserver` 监听容器宽度变化，容器尺寸变化时自动 resize（侧栏折叠、栅格重排都不会把图撑破）。

## 七、数据源切换：SQLite / MySQL

默认用 SQLite（零依赖，开箱即用，仓库已带库文件）。想换成 MySQL：

```bash
cd server

# 1. 准备连接参数（任选一种）
export MYSQL_URL="mysql://root:123456@localhost:3306/clothing_store"
# 也可以分项给：MYSQL_USER / MYSQL_PASSWORD / MYSQL_HOST / MYSQL_PORT / MYSQL_DATABASE

# 2. 一键切换（改 schema provider + .env + 重新生成 Prisma Client）
npm run db:use:mysql

# 3. 建表 + 写种子数据（MySQL 里先手动 CREATE DATABASE，字符集 utf8mb4）
npm run db:push
npm run build && npm run start
```

切回 SQLite（数据不会丢，`dev.db` 一直在）：

```bash
npm run db:use:sqlite
```

> 脚本自动处理两处兼容性差异：MySQL 下把备注/图片类字段标注 `@db.Text`（避免 VARCHAR(191) 截断），切回 SQLite 时再摘掉（SQLite 不认该属性）。切换幂等，来回切无残留。
> SQLite 的 WAL / busy_timeout 与写冲突自动重试在 MySQL 模式下自动跳过（MySQL 由 InnoDB 自行处理锁）。

## 八、并发写安全

- SQLite 启用 **WAL + busy_timeout=8s**（注意：`journal_mode` 这类赋值 PRAGMA 必须用 `$queryRawUnsafe`，用 `executeRaw` 会报错导致 WAL 静默失效）。
- 入库、开单、改单、退货、撤销退货、出库这些多表写操作全部放进 `$transaction`，外面套 `prisma.retryOnBusy()`：
  遇到 `SQLITE_BUSY / database is locked`、MySQL 死锁（1213）与锁等待超时（1205）、Prisma 写冲突（P2034）时指数退避重试，最多 5 次。

## 九、常见问题

**Q：启动后端报 `Environment variable not found: DATABASE_URL`？**
A：先 `cp .env.example .env`（Windows 用 `copy .env.example .env`）。

**Q：`npx prisma generate` 报找不到 schema？**
A：必须在 `server/` 目录下执行（schema 在 `server/prisma/schema.prisma`）。

**Q：前端接口全部 502 / 报错？**
A：后端没起来或端口不是 3000。检查 `server/.env` 的 `PORT` 与 `web/vite.config.js` 的 `proxy.target` 是否一致。

**Q：扫码没反应 / 摄像头打不开？**
A：摄像头扫码需要 **HTTPS 或 localhost** 环境，且浏览器会请求摄像头权限。扫码枪方式不需要摄像头，插上就能用（当键盘用，回车结束）。

**Q：数据库里数据乱了 / 想重置？**
A：删掉 `server/prisma/dev.db` 后重新 `npx prisma db push`，会重新生成一套全新的演示数据。

**Q：怎么把演示库换成自己的数据？**
A：直接用「商品管理」改档案、「门店管理」改门店，或删库重建。**注意改商品货号后，出入库流水里显示的货号会跟着变**（流水表只存 productId，货号是实时关联查的）；销售明细和退货单因为有快照则保持原样。

**Q：登录提示密码错误？**
A：演示账号密码统一 `123456`。若你自己改过密码忘了，可以在「账号权限」页用管理员账号重置。
