# 衣栈 · 服装店多店后台管理系统

前端 **Vue3 + Pinia + Vite + ElementPlus + Axios + ECharts**（纯 JavaScript，无 TS）
后端 **NestJS + Prisma + SQLite**（可一键切换 MySQL）

仓库地址：<https://github.com/mateboys/erp-store-admin>

---

## 一、快速启动

```bash
# 1. 后端（端口 3000）
cd server
npm install
npx prisma generate
npx prisma db push      # 首次执行会自动建库并写入种子数据
npm run start:dev       # 或 npx nest start

# 2. 前端（端口 5173，已配置 /api 代理）
cd web
npm install
npm run dev
```

打开 http://localhost:5173 即可。

> 首次启动后端会自动初始化：3 家门店、商品类别（尼斯分类约 250 条）、演示账号、演示商品与近 60 天销售数据。

## 二、功能清单

### 1. 多店与登录
- 管理员登录后顶部可切换 **「公司总览（全部店）」** 或 **任意分店**，全站数据随切换实时刷新。
- 店长 / 营业员登录后**锁定**在管理员配置的门店，无切换入口，后端也会强制按所属门店过滤数据。

### 2. 权限体系（角色默认权限 + 账号追加授权）

| 权限点 | 管理员 | 店长 | 营业员 |
| --- | :---: | :---: | :---: |
| 查看经营总览 | ✅ | ✅ | ✅ |
| **查看成本 / 毛利 / 毛利趋势** | ✅ | ❌ | ❌ |
| 查看商品 | ✅ | ✅ | ✅ |
| 新增 / 编辑商品 | ✅ | ✅ | ✅ |
| 查看库存 | ✅ | ✅ | ✅ |
| **货品入库（扫码 / 手动）** | ✅ | ❌（可单独授权） | ❌（可单独授权） |
| 销售记账 | ✅ | ✅ | ✅ |
| 查看销售记录 | ✅ | ✅ | ✅ |
| 门店管理 | ✅ | ❌ | ❌ |
| 账号与权限管理 | ✅ | ❌ | ❌ |

> **关于「店长是否可入库」**：需求中前后描述略有出入，这里做成**可配置**——默认店长不可入库，管理员可在「账号权限」页给指定店长勾选追加授权「货品入库」「查看成本与毛利」。菜单、按钮与后端 Guard 三重联动。
> 营业员权限当前与店长一致，后续可在同一页面单独增配。

### 3. 货品入库
- **扫码入库**：摄像头扫码（`@zxing/browser`，支持一维条码 EAN/UPC/Code128 与 QR 二维码），同时支持 **扫码枪键盘输入** 与手动粘贴编码。
- **手动入库**：货号 / 品名模糊搜索选商品 → 进货价、销售价、件数 → 入库。
- 成本采用**移动加权平均**计价；入库后即时更新门店库存与销售价。
- 入库记录可按门店、货号/品名、日期区间查询；非管理员看不到进货价。

### 4. 商品管理
- 新增商品：**货号全局唯一校验**（输入即查重，重复时提示已存在的商品名）。
- 图片上传（可不传，默认占位图）。
- 商品类型：按《类似商品和服务区分表》尼斯分类内置 **第25类 服装鞋帽**（12 个类似群 / 100+ 小类）以及第18/26/24/23 类相关小类，支持**模糊搜索**（如输入「裤子」「T恤」「鞋」）。

### 5. 销售记账
- 搜索货号或品名 → 加入购物车（类似淘宝/京东购物车）。
- 支持多商品、逐行改件数、临时改单价、删除行。
- 汇总总件数 / 应收金额（管理员额外显示成本与毛利）→ 一键统一入账，自动生成订单号并扣减库存。
- 销售记录支持按日期、订单号查询，可查看订单明细。

### 6. 经营总览（ECharts）
- 卡片：今日营业额、今日毛利、本月营业额、本月毛利，并给出**环比**（对比上月同期）与**日环比**（对比昨日）。
- 趋势图：
  - 时间维度：**近 14 天 / 当前月 / 选择某个月 / 近 12 个月 / 自定义起止日期**
  - 指标切换：**营业额趋势 / 毛利趋势 / 双轴对比**
- 门店业绩对比柱状图、本月热销商品 TOP 8。
- 店长 / 营业员看到的总览**不含任何成本、毛利、毛利趋势**，对应卡片与按钮自动隐藏。

### 7. 其它
- 门店管理：新增 / 编辑 / 停用 / 删除，查看各店人员数、库存件数、累计营业额。
- 账号权限：新增账号、改角色、改所属门店、追加授权、停用、重置密码、删除。
- 修改密码。

## 四、技术要点

- **权限三层校验**：前端路由 meta.perm → 菜单/按钮 `v-if` → 后端 `PermissionsGuard`，缺一不可。
- **数据范围隔离**：后端所有查询统一走 `storeWhere()`，非管理员强制 `storeId = 用户所属门店`，避免越权查看他店数据。
- **成本口径**：入库按移动加权平均更新 `Stock.avgCost`，销售按当时均价结转成本，毛利 = 营业额 − 成本。
- **环比口径**：本月 vs 上月同期（上月 1 号至上月同一天），今日 vs 昨日。
- **金额精度口径**：所有钱的计算统一走 `server/src/common/money.ts`（`round2 / lineAmount / lineProfit / sumAmount / subAmount`），
  明细逐行先取整到「分」再汇总 → 单据总额 = Σ 已取整的明细，接口里不再出现 `161.09999999999999` 这类浮点尾巴；
  业务代码禁止再写裸 `toFixed(2)`。

## 五、数据源：SQLite / MySQL 一键切换

默认用 SQLite（零依赖，开箱即用）。想换成 MySQL：

```bash
cd server

# 1. 准备连接参数（任选一种）
export MYSQL_URL="mysql://root:123456@localhost:3306/clothing_store"
# 也可以分项给：MYSQL_USER / MYSQL_PASSWORD / MYSQL_HOST / MYSQL_PORT / MYSQL_DATABASE

# 2. 一键切换（改 schema provider + .env + 重新生成 Prisma Client）
npm run db:use:mysql

# 3. 建表 + 写种子数据（MySQL 里先手动 CREATE DATABASE，字符集 utf8mb4）
npm run db:push
npm run build && npm run start
```

切回 SQLite（数据不会丢，`dev.db` 一直在）：

```bash
npm run db:use:sqlite
```

> 说明：脚本会自动处理两处兼容性差异——MySQL 下把备注/图片类字段标注 `@db.Text`（避免 VARCHAR(191) 截断），
> 切回 SQLite 时再把 `@db.Text` 摘掉（SQLite 不认该属性）。切换是幂等的，来回切不会产生残留。
> SQLite 的 WAL / busy_timeout 与写冲突自动重试在 MySQL 模式下会自动跳过（MySQL 由 InnoDB 自行处理锁）。

## 六、并发写安全

- SQLite 启用 **WAL + busy_timeout=8s**（注意：`journal_mode` 这类赋值 PRAGMA 必须用 `$queryRawUnsafe`，用 executeRaw 会报错导致 WAL 静默失效）。
- 入库、开单、改单、退货、撤销退货这些多表写操作全部放进 `$transaction`，外面套 `prisma.retryOnBusy()`：
  遇到 `SQLITE_BUSY / database is locked`、MySQL 死锁（1213）与锁等待超时（1205）、Prisma 写冲突（P2034）时指数退避重试，最多 5 次。
- 开单在事务内做了**库存二次校验**，避免并发同时卖最后一件货导致超卖。
